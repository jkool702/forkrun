# CK-5 invariants — experimental distributed-ingest engine

Codified invariants for the prototype.

## 8.1 Materialize-before-blocking invariant

**Statement:** a producer must not block on publication admission while
holding a reservation whose data has not yet been materialized.

Implementation: claim → allocate → `di_pread_full` → `di_queue_publish()`.
Publication admission (`di_queue_push`) happens only after `pread` returns
data; the invariant comment is at `di_queue_push` (dist_ingest.c) and in
`dist_ingest.h`.

**DI_INVARIANT_ASSERT build mode:** when built with
`CFLAGS += -DDI_INVARIANT_ASSERT` (or `P.invariant_asserts=1` set at
runtime), `di_invariant_publish_check()` runs at the publication boundary
and asserts chunk data exists + accounting is consistent. Failures print
to stderr. Off by default; never asserted in performance-run builds
(requirement §12).

## 8.2 In-flight accounting invariant

`effective_backlog = published_backlog + consumer_inflight_backlog + outstanding`
(advisory); admission is `effective_backlog <= max_backlog` at claim time
(subject to quantization). Verified at all claim/rollback sites.

**Post-join check (CK-5.2):** in invariant mode, after all engine threads
are joined, each node's `outstanding` must be 0 — asserted in `di_run`;
failure returns `DI_ERR_INVARIANT`.

## 8.3 Relative-adaptive policy law (existing; documented by type)

`r = D_local / D̄_nonlocal` integer arithmetic, rounding mode from
`P.relative_rounding` (0=floor, 1=nearest, 2=ceil), quanta-space.
Byte-level tests pin the tie cases (§8.3, r=0.5 → k+1, r=1.5 → k+2) in
`test_dist_ingest.py`.

## 8.4 Claim/publication granularity (prototype vs intended)

Prototype: one claim = one buffer = one read = one queue entry.
Intended later architecture: batch claims, per-chunk publication.
Documented in `stage0/dist_ingest/DESIGN_NOTES_DEFERRED.md` (CK-7).

## 8.5 DIST_RESULT classification

`DIST_RESULT` includes `"comparability"` block generated from the
maintained plane classification (Accounting/Decision/Lifecycle/Control/
Integrity) with field-level atomic/mutex/advisory annotations.
